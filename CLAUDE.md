# refl

refl — платформа изучения английского (general English + IELTS) для автора и его семьи, дальше возможно открытая. Узбекский и русский как родные языки ученика, интерфейс uz/ru/en. Все решения приняты и записаны в `docs/`. Идёт этап 0.

## Стек

- **Ядро** `core/` — Rust, crate без ввода-вывода: проверка ответов, модель ученика, placement, планировщик. Собирается нативно (сервер) и в WASM (PWA).
- **Сервер** `server/` — axum + tokio + sqlx, PostgreSQL. WebSocket для чата и уведомлений.
- **Клиент** `web/` — TypeScript + SolidJS + Vite, PWA, IndexedDB. Вся логика обучения вызывается из WASM-ядра, в TS её нет. Типы API генерируются из Rust (ts-rs или specta).
- **Контент** `content/` — Nickel → JSON → CLI `content-build` (Rust, на eng-core) → Postgres.
- **Инструменты** `tools/` — `content-build`, симулятор учеников, аудио-конвейер (Piper/Kokoro → Opus).
- FSRS-6 — своя реализация в core на `libm`; fsrs-rs только офлайн для подбора весов.
- Прочее: Hunspell, локальный LanguageTool, Fluent (i18n), tracing + Prometheus + Grafana, pgBackRest.
- **Сборка и деплой:** Nix flake (`flake.nix`), NixOS-модуль, systemd. Монорепо.

## Принципы (не нарушать)

1. **Лог событий — единственный источник правды.** Только дописывается, у события `schema_version`, старые читаются через upcasters. Исправления — новыми событиями (`reclassified`). Снапшоты лишь ускоряют и могут быть удалены.
2. **Ядро детерминировано и чисто.** `fold(state, event) → state`; никакого I/O, времени и случайности внутри (время приходит аргументом). Только `libm` для exp/ln; `BTreeMap`/отсортированный `Vec`, никакого `HashMap` в состоянии. Состояние бит-в-бит одинаково на нативе и в WASM; тест сравнивает хэши.
3. **Offline-first и идемпотентность.** События создаются на клиенте с UUIDv7; синхронизация идемпотентна, конфликтов нет.
4. **Контент как код.** Всё в git, проверки content-build на каждый коммит, id KC и заблуждений не меняются (переименование = новый id + алиас). Событие ссылается на пару (item_id, version).
5. **Проверка ответов детерминированная**, без внешних ИИ-сервисов.
6. **Расширяемость через трейты:** `ItemKind` в core (схема + проверка; отрисовка — компонент в реестре web по типу, на сгенерированных TS-типах, в Rust её нет) и `LearnerModel` (теневые модели сравниваются на реальном логе).
7. **Без хаков и костылей.** Если что-то не ложится в архитектуру — исправляем архитектуру или переписываем правильно, а не обходим. Не добавлять временные обходы «на потом».
8. **Монолит, один сервер.** Микросервисы, очереди, многосерверность намеренно отложены.
9. Производительность закладывается при сборке контента (замыкание графа, автоматы шаблонов, индексы), а не в рантайме.

## Источник правды

- Единственный источник правды — `docs/` в этом репозитории. Спецификации меняются только коммитами.
- Если код расходится со спекой, сначала правится спека (с обоснованием в коммите), потом код.
- Документы в чатах Claude (Claude Docs, артефакты) — архив. Их не читают как актуальные и не правят вместо `docs/`.

## Команды

- Окружение: `nix develop` (или `nix develop -c <команда>`).
- Локальный CI: `nix flake check` — fmt, clippy `-D warnings`, все тесты, сборка `eng-core` под wasm32.
- Одной командой: `just` (в `nix develop`) — fmt-check, clippy, тесты, сборка wasm32, content-build; рецепты по отдельности — `just --list`, полный герметичный CI — `just ci`.
- Тесты: `cargo test --workspace --all-features` (без `--all-features` тест TS-биндингов пропускается).
- Линт: `cargo clippy --workspace --all-targets --all-features -- -D warnings`.
- TS-типы из Rust: `UPDATE_TS_BINDINGS=1 cargo test -p eng-core --all-features --test ts_bindings`; результат в `web/src/generated/core/` коммитится, тест падает, если он устарел.
- `eng-core` по умолчанию `no_std` + `alloc`: в нём нет файлов, сети, часов, потоков, `HashMap` и float-функций std. Фича `std` — только для тестов и инструментов, `ts` — для генерации TS.

## Правила работы

- Отчёты и общение с автором — на английском, коротко, без воды; код, идентификаторы и коммиты — тоже на английском. Критику и собственные идеи высказывать прямо.
- Спека правится до кода. Решения, которых нет в спеке, не принимать молча: сначала спросить, затем закоммитить спеку, потом писать код.
- Перед реализацией читать соответствующую спеку.
- Решения из спек считаются принятыми; открытые вопросы (`Открытые вопросы` в каждом документе) не решать молча — спрашивать.
- Окружение только через `nix develop`. Зависимости добавлять в `flake.nix`/`Cargo.toml`/`package.json`, не ставить глобально.
- Rust: `cargo fmt`, `cargo clippy -- -D warnings`, тесты обязательны для ядра (proptest, пересчёт логов, симулятор). Любое изменение модели ученика — через регрессию на симуляторе и сравнение лог-лосса.
- Не использовать Python/JS как инструмент проекта сверх необходимого клиента на TS; скрипты — на Rust, shell или Nix.
- Задания без диагностических дистракторов/шаблонов ошибок и без привязки к KC в банк не попадают.
- Коммиты небольшие, по одному смыслу. Последняя неделя каждого этапа — только рефакторинг и тесты.
- Секреты не коммитить.
