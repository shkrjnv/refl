# refl — темы, ачивки, рамки

Nov 22, 2026 · @Hara

Темы, ачивки, рамки и компаньоны (docs/06) построены на одной модели разблокировок и на том же логе событий, что и обучение (docs/01, «Социальные функции и инструменты»). Ничто здесь не влияет на обучение: модель ученика, планировщик и контент не зависят от темы, рамки или ачивок.

## Модель разблокировок

Одна сущность на всё, что можно открыть: тема, рамка, компаньон.

| Поле | Значение |
| --- | --- |
| kind | theme, frame, companion |
| key | id пакета (слаг) |
| source | milestone, achievement или admin |

- **Получение — событие в логе** `unlock_granted` (kind, key, source, ссылка на веху или ачивку). Набор открытого у ученика — свёртка лога.
- **Открытое вехой или ачивкой не отбирается никогда.** Выданное админом админ может отозвать событием `unlock_revoked`, например при ошибочной выдаче.
- **Базовые вещи есть у всех** без события: базовая тема, базовый компаньон, базовая рамка.
- **Выбор** темы и компаньона — тоже события (`theme_selected`, `companion_selected`); выбрать можно только открытое.

**Кто пишет производные события.** `milestone_reached`, `achievement_earned` и `unlock_granted` вычисляются из лога и дописываются только сервером после синхронизации. Ключ (ученик, вид, ключ) уникален, поэтому повторное вычисление идемпотентно. Офлайн клиент может показать празднование сразу по своей свёртке, а сервер затем фиксирует событие; вычисление одно и то же, потому что это одно ядро.

**Уникальность и события админа.** Ключ (ученик, тип события, вид, ключ) уникален только для производных событий: `milestone_reached` (вид level или topic, ключ — уровень или id темы), `achievement_earned` (ключ — id ачивки) и `unlock_granted` с источником milestone или achievement. Выдача и отзыв админом (`unlock_granted` с источником admin, `unlock_revoked`) не уникальны: админ может выдать снова после отзыва, текущее состояние — свёртка. Источник указывается ключом (вид и ключ вехи или id ачивки), а не id события, поэтому повторное вычисление даёт тот же payload. События, которые пишет сервер: session_id пуст, client_ts = server_ts = время записи; события админа содержат id админа.

## Темы

Тема — это весь дизайн интерфейса: палитра, шрифты, фоны, облик компаньонов, звуки и анимации. Как устроены токены, которые тема переопределяет, описано в docs/08.

- **Пакет темы:** набор токенов, фоны, звуки, анимации, облик каждого компаньона (отдельный спрайт-лист, docs/06). Новая тема — новый пакет, без изменения кода.
- **Доступ:**
  - базовая тема есть у всех;
  - 5–10 простых тем ученик открывает ачивками;
  - кастомные темы (например, «Блоки», «Сцена») выдаёт админ.
- **«Блоки»:** вайб кубического мира, крупный пиксель, ощущение копания и строительства — да. Название, логотип, узнаваемые текстуры, персонажи, звуки и шрифты Minecraft — нет: всё своё. То же правило для любой темы «в духе» известной игры.
- **Проверки пакета темы при сборке:** контраст текста и элементов не ниже WCAG AA во всех состояниях, наличие всех токенов, облик для каждого существующего компаньона, шрифты покрывают нужные символы (docs/08).

## Ачивки

**Принцип:** награда только за результат, а не за клики, время в приложении или число заданий (docs/01). Случайных ачивок нет: награда, которую нельзя заработать, а можно только «выкрутить», — механика игрового автомата, и чем больше кликаешь, тем больше шансов. У детей она действует сильнее всего.

**Определение ачивки** — условие над свёрткой лога. Поэтому новая ачивка выдаётся задним числом всем, кто её уже заслужил. Условия — именованные предикаты в ядре с параметрами; сама ачивка (предикат, параметры, название, описание на uz/ru/en, картинка) — контент. Новая ачивка на существующем предикате добавляется без кода.

**Виды:**

| Вид | Условие | Что видит ученик |
| --- | --- | --- |
| Обычная | известно заранее | название, условие, прогресс |
| Секретная | реальное, результат обучения, нигде не раскрыто | до получения — только силуэт «?»; после — название и художественное описание, но не точное условие |
| Уникальная | первый в команде, кто достиг вехи | получает ровно один человек в команде; «первый» определяется порядком (server_ts, event_id) |

**Видимость.** Ученик сам решает, какие полученные ачивки показаны в публичном профиле (событие `achievement_visibility_set`). У детей профиль по умолчанию закрыт (docs/01).

**Стартовый список:**

| Ачивка | Вид | Условие |
| --- | --- | --- |
| Первый шаг | обычная | первая освоенная KC |
| Тема закрыта | обычная | первая тема, где освоено ≥ 80% важности KC |
| Уровни A1 … C1 | обычная | веха уровня (docs/06) |
| 30 дней подряд | обычная | серия 30 дней с заморозкой |
| Вылечено | обычная | первое заблуждение в статусе «вылечено» (docs/03) |
| Долгая память | обычная | 20 KC в статусе «надолго» |
| Первый мок | обычная | первый полный мок IELTS (этап 6) |
| 10 книг | обычная | 10 прочитанных текстов библиотеки (этап 3) |
| Встречный ветер | секретная | вылечено заблуждение, активное 21 день и дольше |
| Выше головы | секретная | уверенный верный ответ с вводом на задание KC на два уровня выше уровня ученика |
| Вернул | секретная | KC из статуса «забывается» снова «освоено» без подсказок |
| Точность | секретная | 5 сессий подряд без единой уверенной ошибки при ≥ 20 ответах в каждой |
| Первооткрыватель | уникальная | первый в команде, кто достиг уровня B1 (и отдельно B2, C1) |
| Хранитель темы | уникальная | первый в команде, кто закрыл тему |

Пороги стартовые; секретные условия в интерфейсе не публикуются, но лежат в контенте в git, как всё остальное.

## Рамки

Рамка вокруг аватара показывает уровень ученика: чем выше уровень, тем она детальнее и ярче, у верхних уровней появляется сияние.

- **Уровень рамки — веха уровня** `milestone_reached` (docs/06): рамка не понижается, когда что-то забылось.
- **Ступени:** pre-A1, A1, A2, B1, B2, C1 — по одной на уровень. Сияние — начиная с B2.
- **Стиль** согласован с пиксель-артом компаньонов и с активной темой: каждая тема даёт свой вариант рамок всех ступеней.
- Рамки за отдельные ачивки — не сейчас (открытый вопрос).

## Что закладывается в схему на этапе 0

| Событие | Поля |
| --- | --- |
| `milestone_reached` | веха: level (уровень CEFR) или topic (id KC темы) |
| `achievement_earned` | id ачивки |
| `achievement_visibility_set` | id ачивки, видна ли в публичном профиле |
| `unlock_granted` | вид (theme, frame, companion), ключ пакета, источник: веха, ачивка или админ (id админа) |
| `unlock_revoked` | вид, ключ пакета, id админа |
| `theme_selected` | ключ темы |
| `companion_selected` | ключ компаньона |

События `milestone_reached`, `achievement_earned`, `achievement_visibility_set`, `unlock_granted`, `unlock_revoked`, `theme_selected`, `companion_selected`; уникальность производных событий по (ученик, вид, ключ); настройки приватности профиля. Сами ачивки, темы и рамки — этап 3.
