# Спецификация: лексика, библиотека, заметки и карта знаний

Nov 28, 2026 · @Hara

## Зачем

Этап 3 (docs/01) добавляет к грамматике четыре вещи, которые ученик видит как один связный слой: слова, книги, карту знаний и заметки. Слова живут по FSRS вне графа KC, потому что десять тысяч лемм превратили бы граф в склад без пререквизитов. Книги дают языку контекст, а не ещё один банк заданий. Карта показывает, где ученик находится и почему следующая тема именно эта. Заметки сохраняют мысль там, где она возникла: у правила, слова, задания или страницы книги.

Документ фиксирует границы и правила до кода. Новые типы событий добавляются без повышения `schema_version` (docs/13, «Изменение схемы событий»); новые поля существующих событий не меняются. Всё, что влияет на свёртку, входит в версию модели или `fold_version`; всё, что только показывает, в неё не входит.

## Объём

| Входит в Batch 4 | Не входит |
| --- | --- |
| лексический слой: леммы, значения, формы, IPA, аудио, глоссы uz/ru, FSRS-карточки | speaking, произношение и оценка интонации (docs/05) |
| словарь ученика: свои слова и личные карточки слов из книг | обмен словами между учениками |
| библиотека: справочные объяснения, каталог ловушек L1, книги A1–C1 | reading-экзамен, вопросы к тексту и оценка понимания |
| компилятор книг `tools/book-build`, читалка, персональное покрытие | покупка и продажа книг, внешний книжный магазин |
| карта знаний: слоистый граф на телефоне и «сеть» на компьютере | редактор графа учеником |
| заметки и закладки с офлайн-синхронизацией | публичные заметки, комментарии, совместное редактирование |
| Sendo: контракт ассетов, выбор, путь разблокировки | сюжетные эпизоды Sendo и полный набор реплик |

**Не делаем в Batch 4:** ИИ-пересказ книг, генерацию определений в рантайме, автоматический перевод предложений, облачные заметки вне лога событий, рейтинги «популярные слова» и любые социальные сравнения. Лексика, книги и заметки не меняют критерий освоения KC (docs/03): это отдельные величины и отдельные карточки.

## 1. Лексический слой

### Единица лексики

Единица лексики — **значение слова** (word sense), а не строка. `bank` как «берег» и `bank` как «банк» — два значения с разными определениями, примерами и карточками. Формы слова (bank, banks, banked) принадлежат лемме и не создают отдельных карточек.

| Поле | Тип | Зачем |
| --- | --- | --- |
| `id` | слаг `en.lex.<lemma>.<sense>` | стабильная ссылка значения; префикс `en.lex.` проверяет сборка |
| `lemma` | строка | начальная форма для поиска и показа |
| `pos` | `noun`, `verb`, `adj`, `adv`, `prep`, `pron`, `det`, `conj`, `phrase` | часть речи; влияет на формы и упражнения |
| `frequency_rank` | целое 1…10 000 | частотная полоса; вход порядка слов и покрытия |
| `level` | CEFR pre-A1…C2 | уровень, на котором значение обычно встречается |
| `forms` | список строк | формы леммы для распознавания в тексте; неправильные формы задаются явно |
| `senses` | список значений, ≥ 1 | значения с общими формами, но разными определениями |
| `source`, `license` | строки | откуда данные; лицензия проверяется при сборке |
| `review` | язык → статус и кто проверил | вычитка текста значения; draft ученику не показывается |

Значение (`LexemeSense`):

| Поле | Тип | Зачем |
| --- | --- | --- |
| `id` | слаг `en.lex.<lemma>.<sense>` | стабильная ссылка карточки |
| `definition_en` | строка, не больше 25 слов | простое английское определение для ученика, без круга через само слово |
| `gloss_uz` | строка | узбекский глосс; не перевод определения, а короткое объяснение |
| `gloss_ru` | строка | русский глосс; отдельный текст, не перевод с узбекского |
| `examples` | 1–3 пары «предложение + аудиоключ» | контекст значения; английский текст общий для всех языков |
| `collocations` | 2–5 строк | устойчивые сочетания, которые ученик встретит в книгах |
| `ipa_uk`, `ipa_us` | строки | произношение; IPA хранится текстом, а не картинкой |
| `audio_key` | строка или пусто | ключ аудио; при наличии отдаётся вместе с PWA, без внешнего CDN |
| `review` | язык → статус и кто проверил | `definition_en` и глоссы вычитываются как тексты |

**Идентификаторы.** Лемма и значения — `en.lex.<slug>`; слаг не меняется. Переименование значения — новый id и псевдоним старого. `en.lex.*` не входит в граф `requires` и не становится KC: у слова нет пререквизита, есть частота, контекст и память.

**Объём.** Стартовый банк — 1 500–2 000 лемм уровня A1–A2, не меньше 2 500 значений с учётом многозначности. Целевой объём — 10 000 лемм A1–C1. Банк собирается из частотных списков и учебных словарей; источник и лицензия каждого набора записываются в `THIRD_PARTY.md` до использования (docs/14). Определения, глоссы, примеры и коллокации пишет автор контента; машинный перевод в банк не попадает.

**Вычитка и показ.** У значения есть `review` по языкам, как у объяснений KC. `definition_en` без вычитки не показывается; `gloss_uz` и `gloss_ru` показываются только вычитанные. Если для языка интерфейса нет вычитанного глосса, показывается английское определение, а не машинный перевод. Карточка значения не попадает в сессию, пока его `definition_en` не вычитан; личные слова ученика — исключение, они видны только владельцу.

### Карточки FSRS

У каждого значения — **две независимые карточки FSRS-6**: узнавание (английская форма → смысл) и производство (смысл → английская форма). Это следует открытому вопросу docs/03 о двух навыках слова; модель знания KC к ним не применяется. Карточка хранит:

- `stability`, `difficulty`, `last_review`, `due` — как FSRS-6;
- `direction`: `recognize` или `produce`;
- `exposures` — счётчик пассивных встреч;
- `source`: `bundle` для банка, `custom` для личного слова;
- `review_count`, `lapse_count` — для интерфейса и статистики.

Карточка создаётся не при первом показе слова, а при первом **прямом** свидетельстве: ответ на лексическом упражнении, проверка значения в placement, нажатие «Добавить в словарь» или ответ на карточке повторения. Пассивная встреча в грамматическом задании карточку не создаёт (раздел «Пассивный зачёт»).

Планировщик добавляет лексические повторения в сессию отдельным блоком «Слова» (docs/04, «Сборка сессии»): до 20% времени, только карточки с `due ≤ now`, сначала просроченные. Лексические карточки не входят в `Ready` KC и не блокируют грамматическую тему. Ответ на карточку — обычное событие `answer` с `context = review` и ссылкой на лексический «элемент»; см. раздел «Схема событий».

### Пассивный зачёт из грамматических заданий

Слово, встреченное в правильном грамматическом задании, — слабое свидетельство узнавания, но не повод ставить FSRS-оценку. Поэтому:

1. В проекцию задания (docs/02, «Проекция задания») Batch 4 добавляет `lexemes`: список id значений, которые встречаются в стимуле и в эталонном ответе. Список входит в `fold_version`, потому что от него зависит свёртка.
2. На верный ответ (`correct` или `typo`, не быстрая попытка, без подсказки, первая попытка) каждая карточка `recognize` из `lexemes` получает `exposures += 1` с весом 0,15. На неверный ответ счётчик не меняется: чтение задания не должно наказывать словарь.
3. После трёх разных правильных встреч (разные `item_id`, не одна семья) карточка получает стартовую стабильность 1 день и `last_review` третьей встречи, если прямого свидетельства ещё не было. Дальше пассивные встречи только увеличивают `exposures`; FSRS-интервал они не сдвигают.
4. Прямое свидетельство всегда сильнее: оно обновляет FSRS-карточку обычным путём и обнуляет ожидание «трёх встреч».

Пассивный зачёт не создаёт событий и не пишется в лог отдельно: он выводится свёрткой из уже существующих `answer` событий и проекций. Поэтому старые ответы получают зачёт задним числом, когда бандл добавляет `lexemes`; это меняет `fold_version` и требует полного пересчёта, но не переписывает лог.

### Placement, этап 2

Словарный этап placement (docs/04, «Этап 2: словарный запас») использует тот же банк значений. Его проверки — обычные `answer` события с `context = placement` на заданиях вида `lexeme_probe`:

- `lexeme_probe` — служебный вид задания лексического слоя: стимул — слово или короткая фраза, слот — один, `lexemes` содержит проверяемое значение; при проверке значения варианты ответа — определения, один верный;
- самооценка «знаю / не знаю» — не событие обучения: она управляет только тем, какие слова проверить, и не попадает в свёртку как свидетельство;
- проверка значения даёт сильное свидетельство: верный ответ — `correct`, неверный — `incorrect`; FSRS-карточка создаётся с `review_count = 1`, `stability` из первого интервала и `exposures = 0`;
- псевдослова не имеют `lexemes` и нужны только для индекса завышения; они не создают карточек.

Результат этапа 2 — не новое событие: словарный запас и интервал показываются из свёрнутых карточек, а `placement_completed` остаётся событием общего уровня (`start_level`). Начинающий с нуля этап 2 не проходит (docs/04). Повторный placement раз в месяц обновляет те же карточки обычными ответами.

### Свои слова ученика

Ученик может добавить слово, которого нет в банке, или личную карточку слова из книги. Это **личные данные**, а не контент: они не попадают в общий бандл, не видны другим ученикам, ментору или публичному профилю.

События:

| Событие | Когда |
| --- | --- |
| `custom_lexeme_created` | ученик добавил слово или слово из книги в личный словарь |
| `custom_lexeme_updated` | ученик исправил определение, глосс, пример или контекст |
| `custom_lexeme_archived` | ученик убрал слово из активного словаря; история остаётся |

Поля `custom_lexeme_created` и `custom_lexeme_updated` одинаковы; оба несут полный снимок записи, поэтому свёртка не зависит от порядка создания и обновления:

| Поле | Тип | Зачем |
| --- | --- | --- |
| `custom_id` | UUIDv7 строкой | ключ записи и карточки; равен `event_id` создания |
| `source` | `own`, `book`, `lesson`, `placement` | откуда пришло слово |
| `bundle_lexeme_id` | слаг или пусто | совпадение с банком; даёт IPA, аудио и общие примеры |
| `lemma`, `pos`, `definition_en` | строки | личный снимок слова; не зависит от будущих версий бандла |
| `gloss_uz`, `gloss_ru` | строки | личные глоссы; могут быть пустыми |
| `examples`, `collocations` | списки строк | личный контекст; у слова из книги первое предложение книги |
| `ipa`, `audio_key` | строки или пусто | личное переопределение; при совпадении с банком берутся из банка |
| `context` | `{ text, book_id?, sentence_id? }` или пусто | предложение, в котором ученик встретил слово |
| `archived` | да / нет | активна ли запись |

**Совпадение с банком.** Если `bundle_lexeme_id` указывает на существующее значение в активном бандле, запись становится личной накладкой: она не создаёт второй лексической карточки, а добавляет контекст и личные глоссы к карточке значения из банка. IPA и аудио берутся из банка; личные поля показываются поверх. Если значение исчезло из бандла, запись остаётся приватной карточкой с сохранённым снимком и помечается «слово больше не входит в курс». Если `bundle_lexeme_id` пуст, создаётся личная лемма и две FSRS-карточки.

**SCOWL.** Проверка орфографии личного слова использует тот же SCOWL-словарь, что и ответы (docs/02, «Словарь проверщика»). Если слово есть в SCOWL, но не в банке, оно всё равно остаётся личным: SCOWL — только проверка написания, не определение и не лицензия на контент. Если слова нет и в SCOWL, интерфейс просит подтвердить написание, но не блокирует сохранение.

**Карточки.** Личная запись получает карточки `recognize` и `produce` при создании. Архив не удаляет карточки из истории и не ломает статистику; он убирает их из повторений и из активного словаря. Разархивировать можно новым `custom_lexeme_updated` с `archived = false`; интерфейс Batch 4 этого не предлагает, но свёртка правило знает.

**Частотность и уровень.** У личного слова уровень и частотный ранг пусты. В покрытии книг оно не участвует, пока ученик не добавит его вручную; после добавления оно считается «известным» по своей карточке, но не меняет уровень книги.

## 2. Библиотека и книги по уровням

### Справочная библиотека

Библиотека — это не банк заданий и не читалка. Это справочник, который открывается из карты знаний, заметок и ошибок. В нём только **live-KC** и только **вычитанные** тексты:

- все три глубины объяснения (`short`, `why`, `deep`), каждая отдельной вкладкой;
- блок `l1_contrast` для узбекского и русского — отдельными текстами, а не переводом;
- `refutations` заблуждений — контрастные пары и опровержения (docs/02, «Заблуждение»; docs/10, «Ошибочные правила»);
- каталог ловушек L1: заблуждения с `origin = l1-transfer`, их `affects`, `remedy` и микро-объяснения; только те, у которых есть live-задание или live-тема-лекарство.

Правила показа те же, что у объяснений (docs/02, «Вычитка и показ»): draft не показывается, цепочка языка «интерфейс → ru → en» пропускает невычитанное, у каждого текста виден язык и дата вычитки. Ссылка на объяснение — `#kc/<id>?depth=why&lang=ru`; ссылка на ловушку — `#misconception/<id>`. Никаких персональных данных в библиотеке нет: она целиком собирается из бандла и работает офлайн.

### Компилятор книг

`tools/book-build` — офлайновый компилятор, а не серверный парсер. Он читает исходники книг из `content/books/<book-id>/`, проверяет лицензию и уровень, режет текст на главы, абзацы, предложения и токены и пишет неизменяемый JSON-ассет. Компилятор использует тот же токенизатор и нормализацию, что content-build, поэтому границы слов совпадают с заданиями.

**Исходник.** Манифест `content/books/<book-id>/book.ncl`:

| Поле | Тип | Зачем |
| --- | --- | --- |
| `id` | слаг `book.<slug>` | стабильный id книги |
| `title` | uz / ru / en | название для читалки |
| `level` | CEFR A1…C1 | уровень книги, проверяется покрытием |
| `license` | строка | обязательная лицензия; без неё сборка падает |
| `source` | строка | автор, издание или URL источника |
| `chapters` | список | главы: `id`, `title`, `text` или ссылка на текстовый файл |

**Лицензии.** Допустимы собственные тексты, public domain и лицензии, явно разрешающие использование в закрытом контенте. Каждая книга получает запись в `THIRD_PARTY.md` (что, откуда, лицензия, что требует) и в `content/LICENSE`. CC BY-SA и другие copyleft-тексты не смешиваются с закрытым контентом: если книга под CC BY-SA, её нельзя включать в платный или закрытый сборник без изменения лицензии всего производного. `book-build` падает, если `license` пуста, не известна или требует отсутствующей записи в `THIRD_PARTY.md`.

**Разметка.** Выходной JSON:

```text
book
  id, version, title, level, license, source
  chapters[]
    id, title, paragraphs[]
      id, sentences[]
        id, text, tokens[]
          text, lemma, lexeme_id?, sense_ids[], kc_ids[]
```

`version` — SHA-256 канонического JSON книги; он же `book_version` в событиях закладок. Идентификаторы глав, абзацев, предложений и токенов детерминированы: `chapter.<book>.<n>`, `para.<book>.<chapter>.<n>`, `sentence.<book>.<chapter>.<para>.<n>`, `token.<book>.<chapter>.<para>.<sentence>.<n>`. Порядок предложений — по тексту; перевод строки внутри абзаца не создаёт нового предложения.

**Лемматизация.** Для каждого токена компилятор ищет формы в банке значений, затем в SCOWL. Если найдено одно значение — `lexeme_id`; если несколько — `sense_ids` со всеми кандидатами, а читалка выбирает по контексту и уровню. Если слова нет в банке, `lexeme_id` пуст, но токен остаётся в тексте и в покрытии не учитывается. `kc_ids` заполняются, только если слово явно привязано к KC в контенте; угадывание KC по строке запрещено.

**Проверки.** `book-build` падает, если: лицензия не разрешает использование; уровень книги не A1–C1; в главе нет текста; предложение не разбирается; токен содержит символ вне алфавита предмета; `lexeme_id` не существует; `book_version` не совпадает с содержимым; книга с тем же id уже опубликована с другим `book_version`. Повторная сборка тех же исходников даёт те же байты и ту же версию.

**Доставка.** Книги не входят в бандл: они крупные и меняются редко. Активный бандл содержит `books: [{ id, version, bytes, digest, level, title }]`; читалка скачивает книгу по версии, проверяет SHA-256 и кэширует в IndexedDB. Пара «бандл + книга» не обязана меняться атомарно: книга версионирована отдельно, а закладка хранит `book_version`; если версия исчезла, читалка показывает сохранённый текст закладки и предлагает обновить книгу. Сервер отдаёт книги с `GET /v1/content/books/{version}` и `GET /v1/content/books/{version}/meta`; ответы не содержат личных данных.

### Читалка

- **Одна колонка, крупный текст.** Телефон — 360 px, поля не меньше 16 px, межстрочный интервал по токенам темы; компьютер — мера строки 60–75 символов. Шрифт — Geologica; IPA — отдельным лицом темы, не системным подбором (docs/08).
- **Покрытие.** Над текстом — «понятно ~92%» с кнопкой «откуда это». Покрытие считается из `LearnerState`: доля токенов книги, у которых карточка `recognize` значения имеет `R ≥ 0.8` и хотя бы одно прямое свидетельство. Токены без `lexeme_id` и служебные слова в знаменатель не входят. Если данных мало, вместо процента — «мало данных» и сколько слов нужно проверить. Покрытие не влияет на уровень и не награждается.
- **Тап по слову.** Открывается карточка значения: `definition_en`, глосс языка интерфейса, IPA, аудио, пример из книги и 1–2 общих примера, коллокации, кнопка «Добавить в словарь». Слово с несколькими значениями показывает кандидатов, отсортированных по уровню и частоте; выбор значения запоминается в личной карточке.
- **Добавить в словарь.** Одно нажатие создаёт `custom_lexeme_created` с `source = book`, `bundle_lexeme_id`, контекстом-предложением и выбранным значением. Если запись уже есть, кнопка открывает её, а не создаёт дубль. Для слова вне банка создаётся личная лемма; IPA и аудио подставляются из SCOWL/аудио-кэша, если совпадение найдено.
- **Закладки и выделения.** Долгое нажатие на предложение открывает меню: «закладка», «выделить», «заметка». Выделение хранит диапазон токенов и цвет из токенов темы; закладка — предложение целиком. Всё это события `book_mark_created` / `book_mark_deleted`, приватные по умолчанию.
- **Офлайн.** Текст, проверенный по SHA-256, и закладки работают без сети; прогресс чтения не является событием обучения и не синхронизируется в Batch 4.
- **Доступность.** Тап-зоны не меньше 44 px, есть режим без анимации, выделение не только цветом (иконка и подпись), экран не блокируется оверлеями.

## 3. Карта знаний

### Данные и layout

Карта строится только из live-KC и рёбер, у которых оба конца live. Draft и `observed_only` не показываются: карта — не редактор контента. Для каждой live-KC бандл несёт **предвычисленные координаты** `layout_x`, `layout_y` — целые 0…1000. Их считает content-build, а не клиент: одинаковый бандл даёт одинаковую карту на всех устройствах.

Алгоритм:

1. слой KC — длина самого длинного пути по `requires` от KC без пререквизитов; KC без связей — слой 0;
2. внутри слоя порядок — средняя координата родителей, затем id; циклы `requires` запрещены сборкой;
3. координаты раскладываются по сетке слоёв с детерминированным шагом, нормализуются в 0…1000;
4. рёбра `supports` и `contrasts` не меняют слой, но участвуют в порядке соседей;
5. `layout_x` и `layout_y` входят в бандл и `content_version`, но не в `fold_version`: карта не влияет на обучение.

На компьютере и планшете дополнительно работает «сеть»: force-layout с фиксированным seed (первые 32 бита `content_version`) и стартовыми координатами из бандла. Симуляция выполняется фиксированное число шагов (300) без случайности от времени; результат кэшируется в памяти вкладки. Перетаскивание узла — только локальный вид, в лог и на сервер не пишется.

### Мобильный слоистый граф

- 360 px: вертикальные слои сверху вниз, узлы — карточки с названием KC и статусом; рёбра `requires` — сплошные стрелки, `supports` — пунктир, `contrasts` — точечная линия с подписью «путают».
- Тап-зона узла — не меньше 44×44 px, даже если визуальная карточка меньше; между узлами не меньше 8 px, чтобы промах не открывал соседа.
- Первый тап выбирает KC и подсвечивает соседей; второй тап по соседу переходит к нему; кнопка «назад» возвращает к предыдущему. Панорамирование и масштаб — жестами, без блокировки вертикальной прокрутки страницы.
- Статус показывается не только цветом: иконка и текст (`не начато`, `изучается`, `освоено`, `надолго`, `забывается`), у заблокированной — замок и «сначала …».
- Внизу — компактная легенда и кнопка «найти тему»; поиск фильтрует узлы по названию и id.

### Веб-граф

- «Сеть» на компьютере и планшете: узлы-круги, подписи при наведении и на выбранном узле; рёбра трёх типов с разной формой и цветом токенов.
- Obsidian-подобная подсветка окрестности: выбранный узел и соседи первого шага остаются яркими, остальные приглушаются; повторный тап по соседу расширяет окрестность. Наведение мышью подсвечивает без выбора.
- Клавиатура: `Tab` обходит узлы, `Enter` выбирает, `Esc` снимает выбор; фокус виден кольцом темы.
- Производительность: до 500 live-KC и 1 500 рёбер — 60 fps при панорамировании; при большем числе узлов — Canvas и упрощённые подписи. Анимация только при появлении и при выборе; при «уменьшить движение» — без неё.
- На телефоне «сеть» не включается по умолчанию: слоистый граф читается лучше и не требует точного тапа.

### Стили статусов

| Статус | Вид | Что говорит ученику |
| --- | --- | --- |
| не начато | контур, приглушённый фон | «ещё не проходили» |
| изучается | заливка акцентом, прогресс | «есть ответы, правило ещё не освоено» |
| освоено | зелёная заливка и галочка | «правило держится» |
| надолго | зелёная заливка, значок памяти | «освоено и стабильно» |
| забывается | янтарная заливка, значок часов | «было освоено, память падает» |
| заблокировано | замок, пунктирная рамка | «сначала пререквизит» |

Цвета берутся только из токенов темы; в тёмной схеме проверяется контраст. Заблокированная KC — `Ready < 0.5` по docs/04; она не скрывается, иначе ученик не видит пути.

### Боковая панель

Выбор узла открывает панель (на телефоне — нижний лист, на компьютере — правый drawer):

- название, уровень, важность и статус;
- «Почему это число» — те же величины, что в статистике (docs/09): `M` (вероятность освоения), `R` (память), `σ`, `τ`, сила активного заблуждения; у каждого числа — подсказка «откуда это» и число ответов;
- заметки, привязанные к KC (раздел 4), с кнопкой «добавить заметку»;
- «Практиковать тему» — запускает сессию/урок по KC; если KC заблокирована, кнопка ведёт к самому слабому пререквизиту и объясняет почему;
- «Открыть в библиотеке» — short/why/deep и контраст L1.

Панель не показывает сравнений с другими учениками и не обещает уровень: только текущее состояние и следующий шаг.

## 4. Заметки

### Модель

Заметка — Markdown-текст, привязанный к одному якорю. Заметки живут в логе событий, а не в отдельной таблице: это сохраняет офлайн-первый порядок, экспорт и стирание без второго источника правды.

`note_saved`:

| Поле | Тип | Зачем |
| --- | --- | --- |
| `note_id` | UUIDv7 строкой | стабильный id заметки |
| `anchor.kind` | `kc`, `misconception`, `lexeme`, `item`, `book_mark`, `standalone` | к чему привязана |
| `anchor.id` | строка или пусто | id якоря; пусто только у `standalone` |
| `body` | Markdown, не больше 4 096 байт UTF-8 | текст заметки |

`note_deleted` содержит только `note_id`. Удаление — не физическое удаление события: это tombstone в логе; при экспорте видно и текст, и факт удаления, при стирании аккаунта исчезает всё.

**Якоря.** `kc` и `misconception` берутся из бандла; `lexeme` — значение банка или личное слово; `item` — конкретная версия задания (`item_id@version`); `book_mark` — id закладки/выделения; `standalone` — заметка без привязки. Если якорь исчез из новой версии контента, заметка остаётся, показывается с пометкой «источник больше не входит в курс» и не удаляется автоматически.

**Markdown.** Разрешены заголовки, списки, ссылки, код, цитаты, выделение. HTML, изображения, вложения и исполняемые блоки не поддерживаются. Внутренние ссылки `[[note_id]]` в Batch 4 не создают обратных ссылок; это открытый вопрос, чтобы не обещать граф заметок раньше времени.

**Размер.** 4 096 байт считается по `body` в UTF-8, без заголовка события. Клиент не даёт сохранить больше и показывает счётчик; сервер отклоняет событие с причиной `note_too_large`. Пустой текст — то же, что удаление: клиент пишет `note_deleted`, а не пустой `note_saved`.

### LWW и порядок

Заметки — события-записи: для одного `note_id` побеждает событие с наибольшим `event_id` (UUIDv7), независимо от `client_ts`. Это то же правило, что у настроек (docs/13, «Несколько устройств»), но ключ — `note_id`. `note_saved` после `note_deleted` с большим `event_id` восстанавливает заметку; удаление после сохранения её скрывает. Свёртка не сливает две версии построчно: побеждает последняя целиком, и интерфейс показывает «изменено на другом устройстве», если локальный черновик отличался.

Черновик до сохранения живёт только в IndexedDB устройства и не является событием. Сохранение — по кнопке или при уходе с экрана, не на каждое нажатие: лог не должен пухнуть от набора. После сохранения событие уходит в outbox и синхронизируется обычным путём.

### Приватность

- Заметка видна только владельцу. Она не показывается в публичном профиле, команде, друзьям и ментору, даже если профиль открыт.
- Заметки не используются для рекомендаций, рекламы или аналитики; они не попадают в агрегаты.
- Администратор может увидеть заметку только для поддержки и с записью в журнал доступа (docs/14).
- `/v1/export` включает события заметок и производный список активных заметок; `/v1/erase` удаляет их вместе со всеми событиями ученика. Журнал удалений хранит только id и время, без текста.
- У ребёнка заметки есть, но личных сообщений нет; опекун не видит заметки без явного действия ребёнка. Это правило сильнее обычной видимости профиля.

## 5. Sendo: контракт ассетов и разблокировка

Sendo — второй компаньон (docs/06). Batch 4 добавляет пакет ассетов и путь выбора, но не полный сюжет.

### Контракт ассетов

| Часть | Требование |
| --- | --- |
| спрайты | пиксель-арт 32×32, палитра до 16 цветов, масштаб только ×2/×3/×4, `image-rendering: pixelated` |
| состояния | `idle`, `happy`, `celebrate`, `thinking`, `sleep`, `surprised`; 2–6 кадров на состояние |
| формат | PNG-спрайт-лист + JSON: кадры, длительности, якорь, частота; без сглаживания |
| реплики | Fluent-ключи `uz`/`ru`/`en`, английские реплики по уровням; уровень не выше i+1 |
| темы | необязательный вариант спрайт-листа в пакете темы; без него берётся базовый |
| приватность | реплики и ассеты не содержат личных данных; личная полка ученика не показывается другим |

Ассеты лежат в `content/companions/sendo/` и проверяются content-build: размер кадра, палитра, число кадров, наличие всех состояний, покрытие шрифта для реплик. Новый компаньон — новый пакет, без ветвлений в коде экранов (docs/08, «Тема — пакет данных»).

### Выбор и разблокировка

- Базовый компаньон Iella есть у всех. Sendo открывается вехой библиотеки: первая книга, прочитанная с покрытием ≥ 80% (или первый закрытый зал уровня A2 в библиотеке, если книга ещё не задана). Точный ключ вехи — `library-first-level`; условие проверяется сервером по свёртке и пишется как `milestone_reached`, затем `unlock_granted` с `kind = companion`, `key = sendo`, `source = milestone` (docs/07).
- Выбор — существующее событие `companion_selected` с ключом `sendo`. Если Sendo не открыт, выбор отклоняется клиентом, а сервер не выдаёт `unlock_granted`; старая выбранная Iella остаётся.
- Смена компаньона не теряет прогресс: вехи принадлежат ученику, а не персонажу (docs/06).
- Сюжетные эпизоды и главы Sendo — после Batch 4: сначала пакет, потом текст. В Batch 4 Sendo реагирует на чтение и освоение, но не ведёт отдельную историю.

### Тон

Sendo не комментирует пропуски, не сравнивает учеников, не напоминает о серии дней и не грустит из-за паузы. Пауза — `sleep`, а не «ты меня бросил». Ошибка — «встречный ветер» учёбы, а не разочарование. Реплики проходят те же правила авторства, что задания (docs/06, «Принципы»).

## 6. Схема событий и версии

### Новые типы событий

`schema_version` остаётся 2: добавляются только новые типы, старые ядра сохраняют их как неизвестные и помечают состояние неполным (docs/13, «Неизвестные события»). Ни одно существующее поле не меняется и не становится обязательным.

| Тип | Ключ LWW | Поля |
| --- | --- | --- |
| `custom_lexeme_created` | `custom_id` | `custom_id`, `source`, `bundle_lexeme_id?`, `lemma`, `pos?`, `definition_en`, `gloss_uz`, `gloss_ru`, `examples[]`, `collocations[]`, `ipa?`, `audio_key?`, `context?`, `archived` |
| `custom_lexeme_updated` | `custom_id` | полный снимок, как у `created`; заменяет запись |
| `custom_lexeme_archived` | `custom_id` | `custom_id`, `archived = true` |
| `book_mark_created` | `mark_id` | `mark_id`, `book_id`, `book_version`, `kind` (`highlight`/`bookmark`), `chapter_id`, `paragraph_id`, `sentence_id`, `start_token`, `end_token`, `quote_hash`, `color?` |
| `book_mark_deleted` | `mark_id` | `mark_id` |
| `note_saved` | `note_id` | `note_id`, `anchor {kind, id?}`, `body` |
| `note_deleted` | `note_id` | `note_id` |

**LWW-правила.** Для одного ключа побеждает событие с наибольшим `event_id`; тип не важен, кроме `book_mark_deleted` и `custom_lexeme_archived`, которые несут только признак. `custom_lexeme_created` и `updated` — полные снимки, поэтому свёртка не зависит от порядка. `book_mark_created` после `book_mark_deleted` с большим `event_id` создаёт новую закладку только с новым `mark_id`; повторно использовать удалённый id нельзя. `note_saved` после `note_deleted` восстанавливает заметку.

**Ограничения.**

- `body` — не больше 4 096 байт UTF-8; больше — `note_too_large`.
- `custom_lexeme_*` — не больше 4 096 байт JSON; больше — `custom_lexeme_too_large`.
- `start_token ≤ end_token`, оба — целые ≥ 0 и ≤ 2⁵³ − 1.
- `quote_hash` — 64 шестнадцатеричных символа SHA-256 предложения; не совпал — закладка всё равно принимается, но читалка показывает «текст изменился».
- `book_version` — 64 шестнадцатеричных символа; закладка на неизвестную версию остаётся, но открывается в режиме «сохранённый фрагмент».
- `custom_id`, `note_id`, `mark_id` — UUIDv7 строкой; `custom_id` создания равен `event_id`, у обновлений — id создания.
- Все целые в событиях — не больше 2⁵³ − 1 (docs/02, «Событие и лог»). `bigint` в сгенерированных TS-типах событий запрещён; тест падает.

### Свёртка

Новые события не меняют `LearnerModel::apply` для KC и не входят в критерий освоения. Они складываются в отдельные разделы состояния:

- `custom_lexemes: BTreeMap<CustomLexemeId, CustomLexemeRecord>` — снимок и признак архива;
- `book_marks: BTreeMap<BookMarkId, BookMarkRecord>` — закладки/выделения;
- `notes: BTreeMap<NoteId, NoteRecord>` — активные заметки и tombstone;
- `lexical_cards: BTreeMap<(LexemeId, Direction), LexicalCard>` — FSRS-карточки значений;
- `lexical_exposures: BTreeMap<LexemeId, Exposure>` — пассивный зачёт.

`LexemeId` — либо id банка, либо `custom_id`; карточка не смешивает их. Пассивный зачёт по `answer` использует проекцию задания `lexemes` (Batch 4). Порядок обхода — `BTreeMap`; пассивный зачёт применяется в порядке свёртки событий, а не в порядке показа.

**Версии.** Добавление лексики и `lexemes` в проекции меняет `fold_version`; новые разделы состояния меняют формат снапшота и требуют новой версии модели (`knowledge-v1.4+<хэш параметров>`), поэтому старые снапшоты пересчитываются по логу. `layout_x`/`layout_y` и книги в `fold_version` не входят: карта и чтение не меняют модель. Новый бандл без смены `fold_version` (например, исправление текста книги) пересчёта не требует.

### Хранение на устройстве

Оценка для бюджета docs/13 (50 МБ без аудио, аудио — 200 МБ):

| Что | Оценка |
| --- | --- |
| лексический банк 10 000 лемм / ~15 000 значений | 1,5–2,5 МБ JSON, 0,5–0,8 МБ gzip |
| карточки ученика (до 10 000 значений × 2 направления) | до 1,5 МБ |
| личные слова: до 5 000 × 4 КБ | до 10 МБ (потолок по числу записей — 5 000) |
| заметки: до 2 000 × 4 КБ | до 8 МБ |
| закладки: до 5 000 × ~200 Б | до 1 МБ |
| кэш книг | до 10 МБ, LRU по последнему чтению |
| аудио | отдельный бюджет 200 МБ, LRU |

Итого без аудио — до ~33 МБ, с запасом под снапшот и лог. Счётчики и лимиты проверяются на клиенте; при достижении лимита новые записи не теряются молча: интерфейс предлагает архив/удаление. Книги и аудио вытесняются по давности; личные слова, заметки и закладки не вытесняются, пока ученик сам их не архивирует или не удалит.

### Экспорт и стирание

`/v1/export` отдаёт события как есть (включая `note_saved`, `custom_lexeme_*`, `book_mark_*`) и производный блок `vocabulary` / `notes` / `book_marks` для удобства. `/v1/erase` удаляет все события ученика, включая личные слова, заметки и закладки; журнал удалений хранит только id и время. Это те же функции, что уже покрыты интеграционными тестами Batch 2; Batch 4 добавляет в них новые типы событий.

## 7. Порядок внедрения Batch 4

| Шаг | Что делается | Выход |
| --- | --- | --- |
| 4.1. Контент и ядро | схема `Lexeme`/`LexemeSense`, `lexemes` в проекции, FSRS-карточки, пассивный зачёт, `custom_lexeme_*`, `note_*`, `book_mark_*`; TS-типы | `just content`, тесты свёртки, native = WASM |
| 4.2. Книги и layout | `tools/book-build`, лицензии, `layout_x`/`layout_y`, проверки книг | собранные книги и карта, 0 ошибок |
| 4.3. Доставка и кэш | книги как версионированные ассеты, проверка SHA-256, IndexedDB, лимиты | холодный старт и офлайн-чтение |
| 4.4. Словарь и читалка | placement stage 2, карточки, тап по слову, «Добавить в словарь», личные слова | сквозной путь «увидел слово → повторил» |
| 4.5. Карта и заметки | слоистый граф, «сеть», панель, заметки, закладки | все три размера экрана и офлайн |
| 4.6. Sendo | пакет ассетов, веха, `companion_selected`, тесты | выбор Sendo без потери прогресса |

Каждый шаг заканчивается `just ci`; шаги 4.1–4.2 не включают новые экраны, но обязаны сохранить существующие тесты веб-клиента и бюджеты WASM/JS. Batch 4 не повышает `schema_version`; если при реализации понадобится новое обязательное поле существующего события, работа останавливается и выпускается схема 3 с upcaster, а не тихое изменение.

## 8. Проверки и приёмка

**Контент и ядро.**

- `just content` — 0 ошибок; у каждой книги есть лицензия и запись в `THIRD_PARTY.md`; `layout_x`/`layout_y` детерминированы при повторной сборке.
- `just test` — свёртка `custom_lexeme_*`, `note_*`, `book_mark_*`; LWW по `event_id`; 4 КБ; пассивный зачёт; карточки двух направлений; `fold_version` меняется при добавлении `lexemes`.
- `just wasm-hash` — native и WASM дают одинаковый хэш состояния и плана на логе с новыми событиями.
- `just bindings` — новые типы в `web/src/generated/core/`, ни одного `bigint`.

**Сервер.**

- `/v1/sync` принимает новые типы, повторная отправка идемпотентна; событие с `body > 4 КБ` отклоняется с `note_too_large`; неизвестное старому ядру событие сохраняется как unknown.
- `/v1/export` содержит заметки и личные слова; `/v1/erase` их удаляет; тест не находит текста после стирания.
- `GET /v1/content/books/{version}` отдаёт байты с совпадающим SHA-256; неизвестная версия — 404; ответ не содержит личных данных.
- `/v1/sync` по-прежнему берёт `pg_advisory_xact_lock` по ученику; параллельные пакеты не теряют `server_seq`.

**Клиент.**

- Холодный старт: пустой IndexedDB, скачивание бандла + SCOWL + книги, проверка хэшей, первый экран без ошибки; повторный старт берёт кэш.
- Читалка: покрытие из `LearnerState`, тап по слову, добавление в словарь без дубля, офлайн-перезагрузка, 4 КБ заметка.
- Карта: 360 px, тап-зоны ≥ 44 px, выбор узла, подсветка соседей, «Почему это число», «Практиковать тему»; 1440 px — «сеть» и клавиатура.
- Заметки: LWW на двух устройствах, приватность в публичном профиле, экспорт/стирание.
- Sendo: все состояния и кадры, выбор `companion_selected`, отсутствие упрёков, пауза — `sleep`.
- Бюджеты docs/15: WASM ≤ 500 КБ gzip, JS ≤ 300 КБ gzip, ответ ≤ 50 мс; шрифты и PWA без внешних запросов.

**Приёмка Batch 4** — когда все проверки выше зелёные, холодный старт на телефоне проходит без ручной настройки, а ученик может пройти путь «карта → объяснение → книга → слово → карточка → заметка» офлайн, затем синхронизировать и увидеть то же на втором устройстве.

## Открытые вопросы

1. **Граф заметок.** `[[note_id]]` и обратные ссылки обещаны в docs/01, но в Batch 4 их нет. Нужно решить, хранить ли ссылки как отдельные якоря или вычислять из текста при показе.
2. **Совместные выделения.** Может ли ученик открыть закладку другу или ментору? Пока всё приватно; публичность потребует отдельного события видимости и модерации.
3. **Аудио книг.** Читалка Batch 4 работает с текстом; синхронное аудио и подсветка — после docs/05.
4. **Точность лемматизации.** Для многозначных слов читалка показывает кандидатов; нужен ли контекстный выбор значения в Batch 4 или достаточно ручного?
5. **Веха Sendo.** «Первая книга с покрытием ≥ 80%» — стартовое условие; после пилота его можно заменить на «первый закрытый зал A2».
6. **Локальное шифрование заметок** на общих устройствах — тот же вопрос, что PIN на профиль (docs/13).
7. **Лимит личных слов.** 5 000 выбран как бюджет; если ученики упрутся, archival UX важнее повышения лимита.
