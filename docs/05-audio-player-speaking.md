# Спецификация: аудио, плеер и speaking

Nov 22, 2026 · @Hara

## Границы и решения

Документ описывает три связанные системы: сборку аудио (этап 4), плеер с режимами аудирования (этап 4) и оценку речи ученика (этап 7). Общая основа — время каждого слова и звука: оно нужно и для подсветки текста, и для диктанта, и как эталон для оценки произношения.

**Принятые решения:**

- Аудио — только наше: оригинальные сценарии, озвученные локальным TTS. Темы и факты — из нескольких источников (National Geographic, BBC Future и другие), текст и подача — наши, без пересказа конкретных статей.
- Озвучка генерируется по предложениям, время слов и звуков считает Montreal Forced Aligner при сборке.
- Нажатие на слово ставит воспроизведение на паузу; в настройках это можно выключить.
- Speaking — не чат-бот, а измерительные инструменты: произношение по звукам, интонация и ритм, беглость, лексика и грамматика свободной речи. Всё на локальных моделях и обработке сигнала.
- Ошибки произношения — такие же KC и заблуждения, как грамматические, и идут через ту же модель ученика и планировщик. Отдельной логики для speaking нет.
- Анализ свободной речи асинхронный: ответ приходит через секунды–минуту. Это позволяет обойтись без мощной видеокарты.

## Формат сценария

Сценарий — простой текстовый файл `.script`, который удобно писать руками и читать в диффе. Разбирает его парсер в content-build; ошибка разметки — сообщение с номером строки и столбца, сборка останавливается.

```
@title "Why octopuses are so smart"
@level B1
@topic science
@speakers N: "Narrator" en-GB/af_emma

// пустая строка = новый абзац
N: An octopus has about 500|five hundred million neurons. <400>
N: Most of them are not in its brain but in its {arms}.
N: Scientists are still trying to [[figure out]] how the arms make decisions#choice.
```

**Грамматика** (EBNF):

```
script      = { directive NL } { line } ;
directive   = "@title" string | "@level" cefr | "@topic" ident
            | "@speakers" speaker { "," speaker } | "@source" string ;
speaker     = ident ":" string accent [ "/" voice ] ;
line        = speaker_ref ":" sentence { sentence } NL | comment NL | NL ;
sentence    = token { token } terminator ;
token       = word | mwe | focus | pause ;
word        = letters [ "#" sense ] [ "|" spoken ] ;
mwe         = "[[" word { word } "]]" [ "#" sense ] ;
focus       = "{" ( word | mwe ) "}" ;
pause       = "<" milliseconds ">" ;
```

| Разметка | Смысл |
| --- | --- |
| \`слово | произношение\` |
| `слово#значение` | какое именно значение слова из словаря платформы |
| `[[...]]` | устойчивое выражение, переводится и учится целиком |
| `{...}` | ключевое слово: подсвечивается и попадает в вопросы |
| `<400>` | пауза в миллисекундах при склейке |
| `// ...` | комментарий автора |

Разметка необязательна: без `#` значение выбирается по частотности и помечается «не проверено», числа без `|` раскрываются автоматически. Слабые формы и связки слов вручную не размечаются: их находит сборка (см. диктант).

## Конвейер сборки аудио

Аудио собирается тем же content-build, что и задания: одна команда, воспроизводимый результат, кэш по хэшам. Публикуется только аудио, прошедшее все проверки.

Каждая стадия читает результат предыдущей и пишет свой файл с хэшем входа, поэтому при правке пересобирается только затронутое.

## Озвучка

Каждое предложение озвучивается отдельно и кэшируется по хэшу (текст для озвучки + голос + версия модели). Правка одного предложения переозвучивает только его, а сборка без изменений ничего не генерирует заново.

**Движок.** Основной — Kokoro: звучит естественнее, есть британские и американские голоса, работает на процессоре. Запасной — Piper: проще и быстрее, есть больше акцентов. Оба скрыты за одним интерфейсом, смена движка не трогает остальной сборки. Австралийский акцент для IELTS — открытый вопрос: у локальных движков с ним слабо, нужно сравнить доступные голоса.

**Склейка.** Предложения склеиваются с естественными паузами: 250–400 мс между предложениями, 600–800 мс между абзацами, смена говорящего — 300–500 мс; явная `<мс>` в сценарии важнее. На стыках — короткий кроссфейд (10–20 мс), чтобы не было щелчков. Время предложений в итоговом файле известно точно, потому что его ставит сама склейка.

**Звук.** Громкость приводится к −16 LUFS (EBU R128), чтобы все аудио звучали одинаково. Для ученика — Opus 32 кбит/с моно (около 14 МБ на час), для выравнивания — WAV 16 кГц моно. Отдельно озвучивается каждое слово словаря в изоляции — для кнопки «произнести» в карточке слова.

**Контроль качества озвучки** (TTS иногда проглатывает или искажает слова):

- каждое предложение распознаётся обратно через whisper.cpp и сравнивается с сценарием; доля ошибочных слов (WER) выше порога — перегенерация с другим seed, потом ручная проверка;
- темп речи проверяется по уровню: A1–A2 медленнее, B2+ — естественный темп;
- слишком длинные тишины и обрезанные концы фраз находятся по энергии сигнала.

## Выравнивание и проверки

Montreal Forced Aligner получает WAV каждого предложения и его произносимый текст (правая часть из `|`) и возвращает границы слов и звуков (в фонемах ARPAbet с ударением). Выравнивание идёт по коротким предложениям, потому ошибка в одном месте не расползается по всему файлу.

**Словарь произношений.** База — CMUdict (свободная лицензия, есть ударения). Слова, которых в ней нет, сборка печатает списком; их произношение добавляется в свой файл-дополнение в репозитории, а не угадывается молча. Тот же словарь потом использует speaking как ожидаемые звуки.

**Автоматические проверки выравнивания:**

| Проверка | Признак проблемы |
| --- | --- |
| длительность звука | короче 30 мс или длиннее типичной для этой фонемы в 3 раза |
| тишина внутри слова | слово растянуто на паузу |
| правдоподобие выравнивания | ниже порога, посчитанного по всему контенту |
| согласие с контрольным распознаванием | слова whisper.cpp и сценария расходятся в этом месте |

Предложения с флагами попадают в очередь проверки с прослушиванием и волновой формой; аудио с неразобранными флагами не публикуется.

**Упаковка.** MFA и его акустическая модель `english_us_arpa` фиксируются по версиям в Nix (если в nixpkgs его нет — свой деривейшен или OCI-образ, собранный через Nix). Версия выравнивателя входит в хэш артефакта, поэтому сборка воспроизводима.

## Формат результата

Сборка выдаёт три файла на аудио: Opus, хронометраж слов для плеера и хронометраж звуков для speaking. Звуки вынесены отдельно: плееру они не нужны, а файл с ними в несколько раз больше. Всё версионируется как остальной контент; время в миллисекундах.

```json
{
  "id": "octopus-brain", "version": 3, "level": "B1",
  "audio": { "file": "octopus-brain.v3.opus", "duration_ms": 48210 },
  "speakers": { "N": { "name": "Narrator", "accent": "en-GB" } },
  "segments": [
    {
      "id": "s1", "speaker": "N", "paragraph": 1, "start": 0, "end": 3480,
      "tokens": [
        { "t": "An", "start": 0, "end": 120, "lemma": "a" },
        { "t": "octopus", "start": 120, "end": 640, "lemma": "octopus",
          "sense": "octopus#n1", "cefr": "B1", "freq_rank": 9120 },
        { "t": "500", "spoken": "five hundred", "start": 1010, "end": 1590, "kind": "number" }
      ],
      "features": [ { "type": "weak_form", "token": 5, "form": "əv" } ]
    }
  ],
  "units": [ { "tokens": ["s3:5", "s3:6"], "sense": "figure_out#v1", "focus": false } ]
}
```

- `tokens` — слова в порядке звучания; пунктуация хранится в отображаемом тексте слова, времени у неё нет;
- `features` — найденные сборкой особенности речи (слабые формы, связки, сокращения) для диктанта;
- `units` — устойчивые выражения и ключевые слова, ссылки на слова вида `сегмент:номер`;
- файл звуков имеет ту же структуру, а у каждого слова — список `[фонема, начало, конец]`.

Схема формата описана типами Rust в ядре, TypeScript-типы для плеера генерируются из них.

## Плеер

Плеер ведёт ученика по циклу аудирования: сначала смысл без текста, потом детали, потом текст и интенсивная работа. Текст после попытки, а не до неё, заставляет тренировать именно слух, а не чтение.

| Шаг цикла | Что видит ученик |
| --- | --- |
| 1. Общий смысл | аудио без текста, 1–2 вопроса на главную идею |
| 2. Детали | повторное прослушивание, вопросы на детали в форматах IELTS |
| 3. Текст | синхронная подсветка слов, нажатие на слово — карточка |
| 4. Интенсив | диктант трудных предложений и shadowing |

На уровне A1–A2 шаги 1–2 можно сократить: без опоры на текст новички теряются.

**Карточка слова** (по нажатию, воспроизведение на паузе): слово и начальная форма, транскрипция, перевод именно в этом значении на uz/ru, уровень, звучание слова отдельно и фрагмент из аудио, кнопка «в повторения» (вместе с предложением и его аудио). Для устойчивого выражения показывается всё выражение.

**Управление:**

- нажатие на предложение — переход к нему; кнопки «ещё раз» и «следующее предложение»;
- петля A–B по границам слов (выделить несколько слов — и они звучат по кругу);
- скорость 0,75–1,25 с сохранением высоты голоса (`preservesPitch` в браузере);
- управление с экрана блокировки (Media Session API) и фоновое воспроизведение;
- всё работает офлайн: аудио и хронометраж кэшируются на устройстве.

**Режим shadowing.** После каждой фразы — автопауза на время повторения (длина фразы × 1,2). Фраза — не обязательно предложение: длинные предложения делятся по паузам и запятым на куски не длиннее 4 секунд. До этапа 7 shadowing не оценивается, после — оценивается (см. speaking).

**Технически** подсветка — цикл `requestAnimationFrame`: текущее время аудио → двоичный поиск слова в массиве времён. Стоит микросекунды и не зависит от длины текста.

**В лог пишутся:** нажатие на слово (сигнал «не знает» для лексической модели), повтор предложения (трудное место), скорость, открытие текста и в какой момент.

## Диктант: классификация ошибок

Диктант проверяется не простым диффом, а по причинам ошибок. Введённый текст выравнивается с эталоном по словам (расстояние Левенштейна), затем каждое расхождение сверяется с особенностями речи, найденными при сборке. Каждый класс ошибки — отдельная KC аудирования, и она обновляется обычным путём слоя 2.

| Класс | Как находится при сборке | Пример ошибки | KC |
| --- | --- | --- | --- |
| Слабая форма | служебное слово, в котором MFA увидел редуцированный гласный или выпадение | пропущено of, to, can | `listening.weak-forms` |
| Связка слов | стык «согласный + гласный», выпадение t/d, ассимиляция по звукам MFA | turn off → «turn of» | `listening.linking` |
| Граница слов | расхождение состава слов при похожем звучании | an ice → «a nice» | `listening.word-boundary` |
| Сокращение | I'd, he's, they're в эталоне | I'd → «I» | `listening.contractions` |
| Омофон | совпадающее произношение по CMUdict | their → «there» | грамматика или лексика по контексту |
| Орфография | введённое слово звучит так же, но написано иначе | «becuase» | KC орфографии, не слух |
| Незнакомое слово | низкая вероятность знания в лексической модели | редкое слово искажено | лексика, не слух |

Последние две строки важны: без них система списала бы на «плохой слух» то, что на самом деле орфография или незнакомое слово. Обратная связь показывает не только правильный текст, но и причину: «в быстрой речи of звучит как \[əv\] — послушай ещё раз на 0,75», с воспроизведением именно этого фрагмента по времени слов.

## Speaking: принципы и архитектура

То, что можно посчитать без моделей (тон, громкость, ритм), считается сразу на телефоне в WASM-ядре. То, что требует моделей, уходит в очередь на сервере. Результат любого анализа — обычные события в логе, которые обновляют KC произношения и беглости через модель слоя 2.

&#91;embedded content: архитектура speaking · телефон, очередь, модель\]

- **Очередь — таблица в Postgres** (`SELECT … FOR UPDATE SKIP LOCKED`), без отдельного брокера. Задачи идемпотентны, упавшая задача перезапускается.
- **Обработчик — отдельный бинарник на Rust**: whisper.cpp через привязки whisper-rs, модель звуков через ONNX Runtime (crate `ort`), LanguageTool по HTTP. Его можно запустить на любой машине, в том числе там, где есть видеокарта.
- **Версии моделей фиксируются в событии.** Сменили модель — старые записи, пока они хранятся, можно переанализировать и пересчитать модель ученика, как для остальных событий.

## Произношение

Цель — понятность, а не акцент носителя (принцип интеллигибельности из исследований Левиса, Манро и Дервинг). Поэтому система ищет не любые отличия от эталона, а те, что мешают пониманию, и ранжирует их по функциональной нагрузке контраста: путаница ship / sheep важнее, чем неидеальный /r/.

**Как измеряется.** Модель wav2vec2, обученная распознавать звуки (а не слова), работает через ONNX Runtime из Rust на процессоре и даёт для каждых 20 мс вероятности всех звуков. Ожидаемые звуки берутся из CMUdict с допустимыми вариантами (британский и американский, слабые формы). Выравнивание речи ученика с ожидаемыми звуками — динамическое программирование (Витерби по CTC), несколько десятков строк в ядре; MFA для этого не нужен.

**GOP** (Goodness of Pronunciation) для ожидаемого звука p на его кадрах T\_p — среднее отставание от самого вероятного звука (0 — идеально):

```latex
\mathrm{GOP}(p) = \frac{1}{|T_p|} \sum_{t \in T_p} \Big[ \log P_t(p) - \max_{q} \log P_t(q) \Big], \qquad \mathrm{score}_p = 100\,\sigma\!\left(\frac{\mathrm{GOP}(p) - c_p}{s_p}\right)
```

Пороги c\_p, s\_p калибруются отдельно для каждого звука. Если самый вероятный звук q\* отличается от p и GOP ниже порога — зафиксирована замена p → q\*. Отдельно ищутся выпадения и вставки звуков.

**Точность важнее полноты.** Ложное «ты произнёс неверно» демотивирует сильнее, чем пропущенная ошибка. Пороги подбираются так, чтобы доля ложных срабатываний была низкой, даже ценой пропущенных ошибок.

**Каталог ожидаемых ошибок** — гипотезы, которые нужно проверить на записях учеников пилотной группы. Каждая строка — заблуждение произношения с априорной частотой, как в слое 1:

| Ошибка | Пример | uz | ru |
| --- | --- | :-: | :-: |
| /θ/ → /s/ или /t/, /ð/ → /z/ или /d/ | think → sink | да | да |
| /æ/ → /e/ | bad → bed | да | да |
| /iː/ ↔ /ɪ/ | sheep ↔ ship | да | да |
| /w/ → /v/ | west → vest | частично | да |
| оглушение конечных звонких | dog → dock | возможно | да |
| /h/ → /x/ | house → \[xaus\] | — | да |
| /ŋ/ → /n/ или /ŋk/ | sing → sink | редко (в узбекском есть /ŋ/) | да |
| нет аспирации /p t k/ | pin ≈ bin | да | да |
| нет редукции до швы | to \[tu\] вместо \[tə\] | да | частично |
| гласный перед сочетанием согласных | station → \[isˈteiʃən\] | возможно | — |
| ударение на последний слог | deVElop → deveLOP | да | редко |

**Слух раньше произношения.** Для каждого контраста есть две KC: различение на слух (`phon.ae-e.perceive`) и произношение (`phon.ae-e.produce`), первая — пререквизит второй. Нельзя надёжно произнести то, чего не слышишь.

**Калибровка.** Открытые корпуса речи неносителей с разметкой ошибок по звукам (speechocean762, L2-ARCTIC — лицензии проверить, у L2-ARCTIC она некоммерческая) плюс наши записи, размеченные вручную. Носителей узбекского в открытых корпусах нет, поэтому наши собственные размеченные записи — самая ценная часть калибровки.

## Интонация, ударение, ритм

Это чистая обработка сигнала, без моделей, на Rust в ядре — а значит, работает прямо на телефоне мгновенно. Границы слов и слогов берутся из выравнивания предыдущего раздела, эталон — наше аудио с его хронометражем звуков.

| Что | Как измеряется |
| --- | --- |
| Высота голоса | алгоритм pYIN, перевод в полутоны относительно медианы говорящего: мужской и детский голос сравниваются честно |
| Интонационный контур | контур ученика выравнивается с эталоном по звукам (DTW), считается корреляция и совпадение финального движения (повышение в общем вопросе, понижение в специальном) |
| Словесное ударение | выделенность слога = z-оценки длительности, громкости и движения тона; самый выделенный слог сравнивается с ударением из CMUdict |
| Фразовое ударение | те же признаки на уровне слов: знаменательные слова должны выделяться, служебные — редуцироваться |
| Ритм | nPVI длительностей гласных и %V (Грабе и Лоу, Рамус); английский — язык с ритмом по ударениям, и ровная «пулемётная» речь видна в цифрах |

```latex
\mathrm{nPVI} = \frac{100}{m - 1} \sum_{k=1}^{m-1} \left| \frac{d_k - d_{k+1}}{(d_k + d_{k+1})/2} \right|
```

**Как это видит ученик:** два наложенных контура тона (свой и эталонный) над текстом, ударные слоги крупнее, несовпадения подсвечены. Каждую фразу можно прослушать в двух версиях подряд.

**Оценка shadowing** складывается из четырёх частей, каждая показывается отдельно: звуки (средний GOP), тайминг (задержка и длительности относительно эталона), интонация (корреляция контуров), ударения (доля совпавших). Одно итоговое число скрыло бы, что именно чинить.

## Беглость, лексика, грамматика и IELTS Speaking

Свободная речь (ответ на вопрос без заранее известного текста) анализируется по четырём официальным критериям IELTS. Каждая метрика ниже — известный из исследований автоматической оценки речи (например, SpeechRater от ETS) сигнал, а не наша догадка.

**Распознавание в два прохода.** whisper.cpp (large-v3-turbo, квантованная) даёт текст со временем слов. Но он «исправляет» ученика: дорисовывает -s, -ed, артикли. Поэтому второй проход — та же модель распознавания звуков, что и для произношения, без языковой модели. Она проверяет, есть ли в звуке конечные /s z t d/ и служебные слова, которые написал whisper. Расхождение = пометка «возможно, сказано иначе». Именно так ловятся «he go» и «yesterday I walk».

| Критерий IELTS | Метрики |
| --- | --- |
| Fluency and Coherence | темп (слогов в секунду) и темп без пауз; средняя длина отрезка между паузами; паузы длиннее 250 мс в минуту и доля пауз внутри предложения; «ээ» и самоисправления в минуту; разнообразие связок (however, on the other hand…) |
| Lexical Resource | лексическое разнообразие MTLD (не зависит от длины ответа); доля слов за пределами 2000 самых частых; распределение слов по уровням CEFR; устойчивые сочетания из списка |
| Grammatical Range and Accuracy | набор использованных конструкций (придаточные, условные, пассив, разные времена) по шаблонам частей речи; ошибки LanguageTool + пометки второго прохода; доля предложений без ошибок |
| Pronunciation | средний GOP и найденные замены звуков; словесное ударение; диапазон тона в полутонах (монотонность); уверенность распознавателя как грубый показатель понятности |

**Соответствие вопросу.** Каждой карточке Part 2 автор придаёт списки ключевых слов и синонимов по её пунктам. Система проверяет, какие пункты охвачены, и замечает ответ не на тему. Качество аргументации так не оценить — это чеклист для самопроверки и ментор.

**Оценка band.** По каждому критерию — ординальная регрессия от метрик к band. Сначала связь задаётся вручную по публичным описаниям уровней, потом калибруется на 50+ записях, оценённых тобой и по возможности преподавателем. Пока калибровки нет, общий band не показывается — только интервалы по критериям. Ожидаемая точность после калибровки — примерно ±0,5–1 band, и так и подаётся.

**Обратная связь** — текст ответа с пометками (паузы с длительностью, «ээ», сомнительные места), 2–3 главных приоритета вместо списка из 20 замечаний, аудио образцового ответа и кнопка «ответить ещё раз» с сравнением двух попыток.

## Типы заданий speaking

Задания идут по той же лестнице, что и грамматика: слух → управляемое произношение → свободная речь. Планировщик выбирает их по тем же правилам и формулам, что и остальные.

| Тип | Что тренирует | Как оценивается | Скорость ответа |
| --- | --- | --- | --- |
| Минимальные пары на слух (ship / sheep) | различение звуков | выбор услышанного слова | мгновенно |
| Минимальные пары вслух | произношение контраста | GOP целевого звука | 1–3 с |
| Чтение фразы вслух | звуки, ударение, интонация | GOP + сравнение с эталоном | несколько секунд |
| Повтор за диктором по памяти | обработка речи и грамматика на слух | точность воспроизведения слов и окончаний; известный в исследованиях показатель общего уровня (elicited imitation) | несколько секунд |
| Shadowing с оценкой | ритм, интонация, темп | четыре составляющие из раздела об интонации | десятки секунд |
| IELTS Part 1 | короткие ответы 20–30 с | полный анализ свободной речи | десятки секунд |
| IELTS Part 2 | монолог: 1 минута подготовки, 2 минуты речи по карточке | то же + охват пунктов карточки | до минуты |
| IELTS Part 3 | обсуждение, ответы 40–60 с | полный анализ | десятки секунд |
| Самопрослушивание | осознание своих ошибок | своя запись и образец подряд, без балла | мгновенно |

Режим экзамена для Speaking — полный мок из трёх частей с таймингами IELTS (11–14 минут), вопросы звучат нашей озвучкой, анализ приходит после завершения.

## Ресурсы и железо

Видеокарта не нужна ни для чего, кроме скорости анализа свободной речи. На масштабе пилотной группы и десятков учеников всё помещается на один сервер или виртуальную машину на 8 ядер, 16 ГБ памяти и 100 ГБ SSD. Цифры ниже — ориентиры; скорость моделей проверим бенчмарком на твоём железе.

| Компонент | Где и когда | CPU | RAM | Диск | Видеокарта |
| --- | --- | --: | --: | --- | --- |
| Сервер платформы (axum + Postgres) | постоянно | 2 ядра | 2–4 ГБ | 20 ГБ; лог ≈ 0,4 ГБ в год на 10 учеников | не нужна |
| LanguageTool | постоянно | 1 ядро | 1–2 ГБ | 1 ГБ (+ около 8 ГБ n-gram данных по желанию) | не нужна |
| Аудио-контент | статика через nginx | — | — | ≈ 14 МБ на час; 200 часов ≈ 3 ГБ | — |
| Озвучка (Kokoro, Piper) | при сборке на твоём ПК | все ядра | 2–4 ГБ | модели до 1 ГБ | не нужна, ускоряет |
| Выравнивание (MFA) | при сборке | все ядра | 4–8 ГБ | 2 ГБ | не использует |
| Распознавание речи (whisper.cpp large-v3-turbo) | speaking, очередь | 4–8 ядер | ≈ 2 ГБ | ≈ 0,6 ГБ | желательна |
| Распознавание звуков (wav2vec2, ONNX) | speaking | 2–4 ядра | ≈ 1,5 ГБ | 0,3–1,2 ГБ | желательна |
| Записи учеников | speaking | — | — | Opus 24 кбит/с ≈ 11 МБ на час | — |

**Без видеокарты** короткие задания на произношение считаются за секунды, анализ 2-минутного ответа Part 2 — примерно до минуты на 8 ядрах. Это приемлемо, потому что анализ асинхронный. **С GTX 1660 SUPER** (6 ГБ) обе модели помещаются в память карты, и то же занимает секунды. Для открытого сервиса на сотни активных учеников speaking уже потребует видеокарту или очередь с лимитами.

**Раскладка:** платформа и LanguageTool — виртуальная машина в Proxmox; сборка контента (озвучка, выравнивание) — на твоём ПК по мере надобности; обработчик speaking — отдельный сервис-очередь, который можно запустить там, где есть видеокарта.

## Приватность и открытые вопросы

Записи голоса — личные данные, среди учеников есть дети. Правила закладываются сразу:

- записи хранятся только на нашем сервере, на зашифрованном диске, и никуда не отправляются;
- доступ — у самого ученика и его ментора;
- сырое аудио удаляется через 90 дней, текст и метрики остаются; ученик может оставить себе любую запись вручную;
- записи попадают в калибровку только с явного согласия (у детей — родителя или опекуна);
- выгрузка и удаление всех своих записей — одной кнопкой.

**Открытые вопросы:**

1. **Австралийский акцент** — есть ли приемлемый локальный голос; сравним перед этапом 4.
2. **Модель распознавания звуков:** английская (ARPAbet) или многоязычная (IPA). Многоязычная лучше видит «чужие» звуки вроде \[x\], английская точнее на английских. Решим бенчмарком на записях учеников пилотной группы.
3. **Оценка произношения прямо на телефоне** через onnxruntime-web с небольшой моделью: минимальные пары стали бы мгновенными и офлайн. Нужно проверить точность и скорость на слабых телефонах.
4. **Кто оценивает калибровочные записи** по критериям IELTS: ты и, в идеале, преподаватель с опытом подготовки к IELTS. Без внешней оценки band останется неоткалиброванным.
5. **Лицензии моделей и корпусов** — проверить каждую перед этапом 7, особенно если платформа станет открытой.
